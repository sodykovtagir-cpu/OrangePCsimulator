# Redmi Note 11 Pro: разрешение, picker и стоимость эффектов

## Что установлено по коду и предоставленному логу

- В логе Screen.SetResolution многократно меняет размер от 2400×1080 до
  320×240. В SetupMobileSlider прежний код захватывал Screen.currentResolution
  заново для каждого экземпляра меню. На Android это может быть уже уменьшенный
  render size: 35% от 2400 = 840, а 35% от 840 — уже 294 (прежний нижний
  независимый clamp ширины 320 / высоты 240 дополнительно ломал пропорции).
- Слайдер немедленно вызывал SetResolution и PlayerPrefs.Save на каждом событии.
  Это объясняет длинные серии логов во время перетаскивания и может вызывать
  пересоздание render buffers / сброс motion history. Из одного лога нельзя
  доказать, что слайдер двигался сам, без пользовательского ввода.
- MB=1, затем MB=0 означает изменение ключа PP_MotionBlur, но не доказывает,
  кто это сделал. Автоопределение контролов сканировало подписи соседних строк.
- Декомпиляция входящего NativeFilePicker.aar показала PermissionFreeMode=false
  по умолчанию. Старый gate требует READ_EXTERNAL_STORAGE на Android 6–12;
  RequestPermission возвращает отказ/пустой результат, не запуская picker.
  Реальный fragment уже использует GET_CONTENT/OPEN_DOCUMENT + URI grant,
  копирует выбранный файл в private cache и поддерживает PermissionFreeMode.
  Версия Android / исходная причина отсутствия UI именно на устройстве
  пользователя пока не установлены — это исправление возможного блокера.

## Изменения

1. GraphicsBootstrap.NativeResolution запоминается до первого SetResolution,
   не меняется при открытии новой сцены. Ползунок использует эту же величину.
2. Размер на мобильном вычисляется по единому масштабу .35–1 и сохраняет
   соотношение сторон. Старые повреждённые preferences вроде 320×240 на
   2400×1080 больше не применяются буквально: запрос ограничивается минимумом
   840×378. Выбранное пользователем штатное уменьшение разрешения сохраняется.
3. Серия движений ползунка объединяется: применение после 0.2 s без новых
   событий или при закрытии строки/меню. Одинаковые запросы не отправляются
   повторно. Статический кеш сбрасывается при начале нового Play сеанса.
4. AutoFind прекращает сбор подписей на контейнере с несколькими контролами.
   Инициализация UI не вызывает SetPP, повторный WireAll не добавляет listeners.
   Изменение PP ключей через этот UI теперь имеет отдельную строку журнала.
5. При первом создании JNI-класса включаются PermissionFreeMode=true и
   UseDefaultFilePickerApp=true. Не запрашивается общий доступ ко всем файлам:
   используется уже существующий системный SAF-путь AAR с временным URI-доступом.
6. FileMenu логирует начало выбора / пустой callback, ошибки запуска выводятся
   в Console и messageBox, а не скрываются. Отмена выбора не считается ошибкой.
7. На мобильных blur использует не более 8 сэмплов вместо 16. Удалён лишний
   полноэкранный composite RT + copy из SimpleScreenFx. HDR больше не включается
   только ради blur/виньетки/зерна/AO; при bloom HDR остаётся. Это сокращение
   работы, **не измеренный прирост FPS на Redmi**.
8. StockMotionBlur один раз после 120 рендеров выводит effective settings и
   счётчики active/suppressed frames. Это нужно для дальнейшей диагностики
   слабого blur на ПК: исправление разрешения может убрать частые resets,
   но в данном сеансе проблема ПК не воспроизведена в Unity.

## Проверки

- `test_resolution_stability.py`: 29 assertions над реальным ResolutionSetting
  и bootstrap resolution methods с platform/UI doubles. 100 событий за drag
  дают один запрос, 8 новых меню не уменьшают исходную базу, плохие prefs
  ограничиваются с сохранением пропорций, подписи соседей не смешиваются,
  init не отключает MB. Дополнительно компилируется ветка Windows.
- `test_android_picker_permission_free.py`: 7 проверок реального Android C#
  picker и callback helpers с JNI doubles: режим выставлен до permission gate,
  открытие, callback на Update, отмена, отсутствие дублей, Task completion.
  Имена статических полей и SAF/private-cache path проверены в настоящем AAR.
- Desktop picker: компиляция/маршрутизация Windows, macOS, Linux, фильтры,
  отмена, возврат курсора. Native GUI здесь не запускался.
- Stock blur: 63 C# integration assertions, 14 movement checks, 4 оставшихся
  SimpleScreenFx passes и 6 stock shader fragments компилируются/валидируются;
  71 GPU assertions на синтетических векторах через Mesa/EGL.
- Сохранения: roundtrip OPC3/HMAC, OPC2/legacy, импорт/атомарная запись/кеш/
  recovery и separate-process restart; async menu и screenshot state tests.

C# doubles и headless GPU не заменяют Unity Editor / Android Player / JNI
activity lifecycle. На Redmi и ПК визуально/профайлером изменения здесь
не проверены. Успешная компиляция в пользовательском логе относится к старой
сборке и не является проверкой этих изменений.

## Нерешённые сообщения

`Cannot index save ... Save integrity check failed`:
проверка подписи **не отключена**, файл не удаляется и не переподписывается.
Нужен исходный `.opc` для проверки envelope/HMAC/base64/gzip и совместимости.
Без файла нельзя отличить повреждённый/изменённый сейв от ошибки формата.

`The referenced script ... Game Object '<null>' is missing`:
лог не идентифицирует asset/компонент. Никакие Missing Script компоненты
автоматически не удалялись: так можно уничтожить пользовательские данные.
Нужны дополнительные сведения из Editor/полного лога для точной локализации.

## Проверка на устройстве

- В меню сдвинуть resolution, отпустить и повторно открыть меню 5–10 раз:
  один итоговый запрос после drag, отсутствие кумулятивного падения до 320×240.
- Выбрать 100%, перезапустить: 2400×1080 для этого телефона. Остальные ручные
  значения должны соответствовать проценту от стабильной базы.
- Открыть picker сохранения, выбрать файл / отменить / открыть снова.
  В логе должны быть `[FileMenu] Opening native save picker` и callback либо
  конкретная ошибка. Запустить без общего разрешения на хранилище.
- Включить/выключить Motion Blur и сравнить CPU/GPU frame time с теми же
  bloom/reflections и фиксированным разрешением. После 120 рендеров сохранить
  строку `[StockMotionBlur]` отдельно для ПК и телефона.
