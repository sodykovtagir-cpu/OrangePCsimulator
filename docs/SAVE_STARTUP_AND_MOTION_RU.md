# Ранний кеш сейвов, устойчивый импорт и Motion Blur

## Загрузка

`SaveStartup.Begin` использует Unity `BeforeSplashScreen`: начинает чтение
сохранений до первого меню, в наиболее ранней точке, доступной игровым скриптам.
Это не изменение самого загрузчика/логотипа Unity. Метод захватывает постоянный
путь на главном потоке, а `SaveCatalog` читает файлы, проверяет HMAC и декодирует
заголовки в Task worker. `JsonUtility` вызывается только для обычных serializable
данных без UnityEngine.Object; создание текстур и объектов UI остаётся на main.

Кеш хранит заголовки/метаданные, не все развёрнутые игровые миры. Проверяет размер
и UTC-время файла, обновляется после записи/импорта/удаления и при открытии меню.
Повреждённые записи фиксируются с ошибкой; список не блокируется на их разборе.
`SaveStartup` заранее подготавливает обложки по одной за кадр; кеш ограничен
64 обложками и 8 MiB декодированных RGBA-текстур. Обычные скриншоты сейвов 128x128;
слишком большие/не-PNG обложки не декодируются. На lowMemory кеш освобождается.
Устаревшие картинки удаляются при обновлении каталога, а не копятся после Save.

FileMenu.OnEnable не вызывает Directory.GetFiles/чтение сейвов/распаковку JSON.
Переход сначала получает кадр, затем строки создаются пакетами не более восьми
или около 3 ms UI-работы за итерацию. Закрытие/повторное открытие отменяет старое
построение; очистка большого прежнего списка тоже разбита по кадрам. Если раннее
чтение ещё не закончилось, меню асинхронно ждёт — главный поток не блокируется.

Нажатие на конкретный сейв также сначала показывает Loading; полная проверка и
распаковка выполняются worker-ом, затем обычная загрузка сцены продолжается на
главном потоке. Это не отменяет время создания предметов/физики в самой сцене.

## Android и запись

Оба входа импорта — NativeFilePicker и ACTION_VIEW/«Открыть с помощью» — используют
SaveFileImport. Временный файл Android не становится рабочим путём сейва:
после проверки данных создаётся отдельный `.opc` в `persistentDataPath/saves`,
полностью записывается и повторно открывается. Только затем импорт подтверждён.
Повторный импорт не затирает существующий сейв; .pc и прежние OPC2/XOR читаются,
результат записывается современным OPC3. Очистка Android cache не удаляет копию.

Прежний `File.WriteAllText` в DataLoader обнулял единственный файл до окончания
записи. Теперь SaveStorage пишет `.pending`, выполняет Flush(true), затем
атомарную замену с `.bak`. На платформе без File.Replace используется перенос
с возвратом прежнего файла при ошибке. При следующем запуске проверяется основной
файл и при необходимости восстанавливается исправный pending/backup. Исправный
основной файл не заменяется старой копией. Повреждённый оригинал сохраняется как
`.damaged-*` для диагностики. Явное удаление убирает и sidecar-файлы, поэтому
удалённый пользователем сейв не восстанавливается сам.

Это устранение небезопасных путей записи/импорта; точное исчезновение на конкретном
Android-устройстве здесь не воспроизводилось. Следует проверить APK: импорт через
оба входа → игра → Save/Home → принудительная остановка приложения → новый запуск.
Если файл исчезает и после обновления, нужны Android logcat и содержимое saves.
Потерянный ранее файл без резервной копии эти изменения восстановить не могут.

## Motion Blur

CharacterController перемещается раз за Update, после обработки поворота камеры,
с Time.deltaTime. Раньше перемещение происходило в FixedUpdate, а камера и экран
обновлялись с другой частотой: при беге визуальная скорость скакала между кадрами.
Скорости ходьбы/бега, гравитация, шаги и обработчики столкновений сохранены;
проверка отключённого CharacterController во время LoadPlayer также сохранена.
Сила толкания Rigidbody компенсирована отношением render/physics deltaTime, чтобы
частота кадров не увеличивала силу толчка при более частых вызовах Move.

Эффект использует camera/object motion vectors там, где они поддерживаются;
на остальных GPU — ограниченный камерный fallback с учётом движения вперёд.
Для MB включены depth и, при поддержке, motion-vector texture. Размытие работает
по текущему кадру, без накопления старых цветовых кадров; ширина ограничена
12 пикселями, 13 сэмплов дают расстояние не более пикселя. По глубине подавляется
растаскивание резко отделённых объектов на фон. Fallback приближённый, не замена
настоящих motion vectors движущихся объектов на неподдерживаемом GPU.

История движения сбрасывается после паузы, включения/выключения эффекта, пропуска
кадров, изменения FOV/разрешения, телепорта и резкого скачка поворота. Повторный
Camera.Render для иконки сейва не обновляет состояние эффекта. Bloom/зерно/AO и
виньетка не удалены; FX по-прежнему выключен целиком при выключенных настройках.

## Проверки

- test_save_startup_and_durability.py: 15 реальных файловых проверок + 4 проверки
  отдельным новым процессом: импорт/очистка cache, запись прогресса, HMAC,
  инвалидирование метаданных, восстановление pending/backup, явное удаление.
- test_save_menu_async.py: компиляция настоящих FileMenu/MainMenu/SaveStartup и
  7 исполняемых проверок coroutine, пакетного построения и открытия worker-ом.
- test_motion_blur_stability.py: настоящий SimpleScreenFx и выбранный метод
  движения с doubles движка: 25 проверок, в том числе 30/60/90/120/144/240 FPS.
  Все четыре настоящих HLSL-прохода с UnityCG shim компилируются glslang и
  проверяются spirv-val. Это не компиляция Unity ShaderLab для конкретного GPU.
- Прежние проверки OPC3/OPC2/legacy, экспорта, Android Open with и неизменённых
  boxed-ready-delivery также проходят.

Unity 2022.3 Editor/Play Mode и Android APK на устройстве здесь не запускались.
Известные старые source-guard suite test_requested_hotfixes.py и
 test_cable_mode_branches.py спотыкаются о прежние, не связанные с этой задачей
проверки FileManager/имён настроек сцены; это не заявляется как успешный полный
прогон всех тестов репозитория.
