# Server physics diagnostic

In Unity 2022.3, enter Play Mode and load a room. Run **Tools → OrangePC → Server physics diagnostic**, then inspect the Console `[ServerPhysics]` messages. It spawns `ReadyServer_Entry` in an isolated area, waits for the normal builder and factory slots, shoots the real `Raycast.ShootRaycast` at the chassis, and samples physics for 150 fixed steps. It reports max part drift and rotation relative to the chassis, chassis speed and angular speed after an initial transient, lost bodies, and board-related solid collider penetrations. PASS requires drift < 0.08 m, relative rotation < 4 degrees, and chassis speed < 0.3 m/s and spin < 1 rad/s after the transient. These are diagnostic thresholds, not game-design specifications.

The second run removes the motherboard **and its installed child components**; this is an A/B localization aid, not proof that the board alone is responsible. Overlap messages exclude triggers and disabled layer pairs, but `ComputePenetration` does not account for joint contact suppression: an overlap is a lead, not necessarily an active contact. Check the full run's `BOARD OVERLAP` messages and compare both runs. Setup errors explicitly fail rather than silently passing. The tool restores the grid state and cleans up its test objects; do not run during another active drag.

Static inspection: the server board mount is at y=-0.17, the board root box extends 0.0200001 down, and the chassis floor top is about y=-0.1964243. Thus their nominal clearance is only ~0.0064 m while the project default contact offset is 0.01 m per collider. Board child colliders also remain on layer 0 while the installed board root changes to layer 8; some of these child colliders can contact installed parts. Both are leads requiring the Play Mode diagnostic; they do not prove the source of shaking. No board geometry was changed without runtime evidence.
