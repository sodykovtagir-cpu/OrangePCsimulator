# Серверы в магазине

## Исправленный состав каталога

**13 серверных товаров** в обычных вкладках, без отдельных новых линеек RAM, HDD и кулеров:

- Case: Server — 350; запасная Server Cover — 40.
- Processor: 7 RMD Threadripper — 1920X (850), 2920X (1000), авторский 3960X (1250), 3970X (1700), 3990X (2500), PRO 5975WX (2100), PRO 5995WX (3300).
- Motherboard: авторская Server ATX — 650, 2 CPU/14 DIMM/2 кулера.
- Power Supply: тонкий серверный БП 2000 W — 350. Старое имя ресурса PSUThin_2000kW сохранено.
- Cooler: только авторский ServerCooler — 85. Для него используется новая авторская иконка `Assets/Texture2D/servercooler.png`.
- Storage: запасная Server HDD Tray — 25.

ServerCooler Pro/Max, RAM Server ECC 32/64/128GB и HDD Enterprise 8/16/20TB **удалены**: и магазинные ассеты, и лишние префабы, и их метаданные. Генератор не возвращает их при повторном запуске. Существующие обычные RAM/HDD, их цены, изображения и вкладки не меняются.

## Готовые серверы

Отдельная вкладка «Готовые серверы». По последнему указанию пользователя все четыре сборки используют **общий ReadyBuildSpawner, как обычные готовые ПК и майнеры**. Префабы ReadyServer_* теперь содержат только план сборки: basePrefab=Server и список обычных префабов деталей. Создание компонентов и установка через Slot.TryAttach выполняются штатным скриптом; авторские модели и посадки не генерируются и не меняются. Используются обычные RAM/HDD из игры и один исходный ServerCooler на каждый CPU.

| Сервер | CPU | Обычная RAM | Обычные HDD | Сумма деталей | Цена |
|---|---|---|---|---:|---:|
| Orange Rack S1 | 1×1920X | 2×32 = 64 GB | 2×2 TB | 3205 | 3530 |
| Orange Rack Storage | 1×3960X | 4×32 = 128 GB | 4×8 TB | 4965 | 5465 |
| Orange Rack Compute | 2×3970X | 8×64 = 512 GB | 2×16 TB | 11680 | 12850 |
| Orange Rack Ultra | 2×PRO 5995WX | 14×64 = 896 GB | 4×20 TB | 20560 | 22620 |

Цена — сумма деталей + 10%, округление вверх до 5. RAM 32/64GB — 380/760, HDD 2/8/16/20TB — 80/190/340/450, непосредственно из существующих ShopItem. В Ultra нет выдуманной RAM 128GB. Крышка и четыре корзины включены в цену корпуса, повторно не оплачиваются. Видимость и посадки исходных частей наследуются из авторских префабов.

На одном HDD установлен PCOS с Info, Disk, Downloader, Browser, Benchmark; остальные HDD пустые. Lua Editor автоматически не ставится.

Планы создаются теми же `ReadyBuild.resolve` и `write_spawner_prefab`, что у обычных готовых ПК. Питание и HDD устанавливаются до платы; CPU/кулеры/RAM — после неё. Четыре заводские корзины уже присутствуют в обычном Server, второй комплект корзин спавнер не создаёт. PCOS устанавливает общий `InstallSystem` на первый созданный диск; исходные префабы HDD остаются пустыми.

`ServerChassis` продолжает подключать только заводские крышку/корзины исходного корпуса. На новых покупках `factoryParts` пуст. Старые сохранения с корневыми spawnId ReadyServer_Entry/Storage/Compute/Ultra через SaveManager получают обычный Server вместо покупочного плана; сохранённые CPU/RAM/HDD и их связи восстанавливаются отдельно. Это не даёт загрузке повторно собрать новый комплект деталей поверх уже сохранённого.

## Доставка в коробке

**И пустой Server, и все четыре готовых сервера продаются в закрытом ящике под габариты сервера.** Эталон — пользовательский `Crate_ReadyServer_Compute.prefab` из коммита `8866bbf`, модель — `Assets/Models/serverbox.fbx`.

Настройки Compute перенесены на Entry, Storage, Ultra и Crate_Server: меши и материалы, позиции/повороты, размеры и центры коллайдеров, Rigidbody и прочие параметры компонентов. Масштабы остались единичными. Не заменяется только идентичность каждого ящика (имя/spawnId, GUID и локальные fileID) и его собственная ссылка на содержимое. Сам Compute геометрически не менялся; в нём только добавлен флаг нормальных столкновений.

- Смещение выдачи у всех одинаковое, авторское: **position=(0, 0, -1.67), rotation=(0, 0, 0)**. Старое смещение y=-1.855 удалено.
- Закрытая коробка не содержит живой сборки. Crate вскрывается молотком и активирует BrokenCrate/ReadyBuildBox. Пустой корпус выдаётся напрямую, готовый — через общий ReadyBuildSpawner.
- **Обломки всех серверных ящиков сталкиваются с сервером и его деталями.** У ReadyBuildBox добавлено сериализованное `ignoreDebrisCollisions`, для всех пяти серверных ящиков установлено **0**. Поэтому не запускается ни FreeFromDebris для пустого корпуса, ни передача DeliveryDebris в сборщик. Все коллайдеры обломков включены, не триггерные; Rigidbody и слои сохранены из Compute.
- У обычных готовых ПК/майнеров прежнее поведение не меняется: значение по умолчанию — true. Это не глобальное отключение или включение коллизий для всех коробок игры.
- `tools/sync_server_crates.py` повторяет перенос с текущего Compute с сохранением локальных ID и метаданных. Catalog.delivery также вызывает этот механизм, а не генератор стандартного ящика ATX. Это не даст следующему запуску генератора вернуть старые размеры/обломки/смещение.

Пять ящиков находятся в `Assets/Resources/components/servers/`. Тесты подтверждают совпадение настроек и отсутствие вызовов IgnoreCollision на серверном пути; безопасность реального вскрытия в PhysX требует Unity Play Mode.

## Изображения

- Все RMD используют пользовательский `Assets/Texture2D/RmdServer.png`; сам PNG и UV-текстуры CPU не меняются.
- Server и все готовые серверы используют авторский `server.png`; ServerCooler — авторский `servercooler.png`. PNG и их метаданные не изменены. Устаревшая сгенерированная Chassis.png удалена.
- Новые изображения RAM и HDD удалены вместе с лишними линейками. Обычные товары используют свои штатные спрайты.
- Остались четыре изображения для уникальных серверных моделей без найденного соответствующего готового спрайта: плата, тонкий БП, крышка, корзина. Это рендеры реальных мешей. `thinpsu2kw.png` — UV-развёртка БП, не магазинный спрайт; её не следует выдавать за обложку. Штатный Power Supply 2kW изображает другой, обычный БП.
- **Для будущих обложек сначала искать существующий спрайт. Если его нет — сверяться со стандартными обложками аналогичной категории, подбирая тот же ракурс, перспективу/FOV и масштаб в кадре.** Подробности в `docs/ASSET_COVER_GUIDELINES_RU.md`. Не считать произвольную ортографическую камеру стандартом игры.

## Совместимость с авторскими изменениями

Учтён пользовательский коммит `41e242f`: обновлённые ServerFan, исходный ServerCooler, положения/повороты посадок Server ATX, совместимость кулера и изменения Server. Эти исходные модели/префабы не перезаписываются; готовые серверы повторно сформированы из их актуального состояния. Проверка охлаждения использует настоящий CoolerSearchRadius из CPU.cs, а не прежнее искусственное ограничение 0.10.

Перенос старого отдельного `Resources/components/Server.fbx` в `Models/LegacyServer.fbx` сохранён: GUID не меняется, ссылки BigMiner действительны, конфликт имени ресурса с Server.prefab устранён.

```bash
python3 tools/sync_server_crates.py
python3 tools/generate_server_catalog.py
python3 tools/export_server_cover_scenes.py
python3 tools/finalize_server_covers.py
python3 tools/test_server_catalog.py
python3 tools/test_server_trays.py
python3 tools/test_ready_delivery_debris.py
python3 tools/test_server_crate_settings.py
```

Для полного повторного рендера между экспортом и финализацией:

```bash
blender -b -t 4 --python-exit-code 1 -P tools/render_server_covers.py -- --root .
```

Текущая камера этого инструмента воспроизводит прежние серверные картинки, но не является обязательным шаблоном будущих обложек: их следует сначала калибровать по стандартным изображениям игры.

Тест каталога проверяет 13 товаров, отсутствие лишних линеек, прежние товары/их порядок, GUID/fileID/физику, общий ReadyBuildSpawner и состав его плана, сокеты, питание, охлаждение, одну PCOS, обычную RAM/HDD и точные цены, авторские иконки корпуса/кулера, пять ящиков, неактивность содержимого до вскрытия, авторские настройки Compute и нормальные столкновения серверов с обломками, смещение выдачи и идемпотентность генератора. `test_ready_delivery_debris.py` исполняет настоящий ReadyBuildBox и метод защиты общего сборщика на engine doubles; проверяет отсутствие IgnoreCollision для серверного плана и пустого корпуса, прежнюю защиту обычных ПК/майнеров и маршрутизацию старых сохранений. Tray-тест исполняет реальный C# код компонентов с минимальными engine doubles, включая разборку и очистку заводских деталей при загрузке.

**Unity Editor здесь недоступен: полная компиляция и Play Mode не выполнялись.** В Unity нужно проверить доставку пустого корпуса и четырёх сборок, падение закрытой коробки, вскрытие молотком на полу, запуск PCOS, ручную установку кулера, снятие/возврат корзин и сохранение/загрузку закрытого ящика и частично разобранной сборки.
