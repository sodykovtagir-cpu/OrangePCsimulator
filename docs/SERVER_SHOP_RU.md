# Серверы в магазине

## Исправленный состав каталога

**13 серверных товаров** в обычных вкладках, без отдельных новых линеек RAM, HDD и кулеров:

- Case: Server — 350; запасная Server Cover — 40.
- Processor: 7 RMD Threadripper — 1920X (850), 2920X (1000), авторский 3960X (1250), 3970X (1700), 3990X (2500), PRO 5975WX (2100), PRO 5995WX (3300).
- Motherboard: авторская Server ATX — 650, 2 CPU/14 DIMM/2 кулера.
- Power Supply: тонкий серверный БП 2000 W — 350. Старое имя ресурса PSUThin_2000kW сохранено.
- Cooler: только авторский ServerCooler — 85. Для него используется существующий `Assets/Sprite/Cooler.asset`, связанный с `Cooler_0.png`.
- Storage: запасная Server HDD Tray — 25.

ServerCooler Pro/Max, RAM Server ECC 32/64/128GB и HDD Enterprise 8/16/20TB **удалены**: и магазинные ассеты, и лишние префабы, и их метаданные. Генератор не возвращает их при повторном запуске. Существующие обычные RAM/HDD, их цены, изображения и вкладки не меняются.

## Готовые серверы

Отдельная вкладка «Готовые серверы». Все сборки — заранее собранные **полные префабы**, без ReadyBuildSpawner и без генерации геометрии при появлении. Используются обычные RAM/HDD из игры и один исходный ServerCooler на каждый CPU.

| Сервер | CPU | Обычная RAM | Обычные HDD | Сумма деталей | Цена |
|---|---|---|---|---:|---:|
| Orange Rack S1 | 1×1920X | 2×32 = 64 GB | 2×2 TB | 3205 | 3530 |
| Orange Rack Storage | 1×3960X | 4×32 = 128 GB | 4×8 TB | 4965 | 5465 |
| Orange Rack Compute | 2×3970X | 8×64 = 512 GB | 2×16 TB | 11680 | 12850 |
| Orange Rack Ultra | 2×PRO 5995WX | 14×64 = 896 GB | 4×20 TB | 20560 | 22620 |

Цена — сумма деталей + 10%, округление вверх до 5. RAM 32/64GB — 380/760, HDD 2/8/16/20TB — 80/190/340/450, непосредственно из существующих ShopItem. В Ultra нет выдуманной RAM 128GB. Крышка и четыре корзины включены в цену корпуса, повторно не оплачиваются. Видимость и посадки исходных частей наследуются из авторских префабов.

На одном HDD установлен PCOS с Info, Disk, Downloader, Browser, Benchmark; остальные HDD пустые. Lua Editor автоматически не ставится.

`ServerChassis.factoryParts` только подключает уже вложенные Item к слотам. При восстановлении сохранения заводские копии удаляются, а компоненты загружает SaveManager. Геометрия не создаётся этим скриптом.

## Доставка в коробке

**И пустой Server, и все четыре готовых сервера продаются в закрытом деревянном ящике.**

Цепочка доставки: ShopItem.spawn → `Crate_Server` / `Crate_ReadyServer_*` → Crate → неактивный BrokenCrate → ReadyBuildBox.prefab → полный префаб сервера.

- Используется стандартный ящик `Crate_Case_ATX 2(Black)` с единичным масштабом; новые меши коробки не создаются.
- В закрытом ящике нет живого сервера, CPU или дисков. При доставке физические удары приходятся на ящик, а не на компоненты.
- При ударе молотком Crate активирует BrokenCrate и удаляет целую коробку. ReadyBuildBox выдаёт один существующий полный префаб, а не собирает детали скриптом.
- ReadyBuildBox штатно отключает столкновения груза с обломками ящика.
- Box.position настроен по коллайдерам груза: низ сервера появляется примерно на 0.15 выше дна ящика, а не в его центре. Это уменьшает высоту падения после вскрытия стоящей на полу коробки.
- Имена файлов/корневые spawnId ящиков совпадают для сохранения через Resources.

Пять ящиков находятся в `Assets/Resources/components/servers/`.

## Изображения

- Все RMD используют пользовательский `Assets/Texture2D/RmdServer.png`; сам PNG и UV-текстуры CPU не меняются.
- ServerCooler использует уже существующий `Assets/Sprite/Cooler.asset`. Новая дублирующая обложка кулера удалена.
- Новые изображения RAM и HDD удалены вместе с лишними линейками. Обычные товары используют свои штатные спрайты.
- Остались пять изображений для уникальных серверных моделей без найденного соответствующего готового спрайта: корпус, плата, тонкий БП, крышка, корзина. Это рендеры реальных мешей. `thinpsu2kw.png` — UV-развёртка БП, не магазинный спрайт; её не следует выдавать за обложку. Штатный Power Supply 2kW изображает другой, обычный БП.
- **Для будущих обложек сначала искать существующий спрайт. Если его нет — сверяться со стандартными обложками аналогичной категории, подбирая тот же ракурс, перспективу/FOV и масштаб в кадре.** Подробности в `docs/ASSET_COVER_GUIDELINES_RU.md`. Не считать произвольную ортографическую камеру стандартом игры.

## Совместимость с авторскими изменениями

Учтён пользовательский коммит `41e242f`: обновлённые ServerFan, исходный ServerCooler, положения/повороты посадок Server ATX, совместимость кулера и изменения Server. Эти исходные модели/префабы не перезаписываются; готовые серверы повторно сформированы из их актуального состояния. Проверка охлаждения использует настоящий CoolerSearchRadius из CPU.cs, а не прежнее искусственное ограничение 0.10.

Перенос старого отдельного `Resources/components/Server.fbx` в `Models/LegacyServer.fbx` сохранён: GUID не меняется, ссылки BigMiner действительны, конфликт имени ресурса с Server.prefab устранён.

## Проверки

```bash
python3 tools/generate_server_catalog.py
python3 tools/export_server_cover_scenes.py
python3 tools/finalize_server_covers.py
python3 tools/test_server_catalog.py
python3 tools/test_server_trays.py
```

Для полного повторного рендера между экспортом и финализацией:

```bash
blender -b -t 4 --python-exit-code 1 -P tools/render_server_covers.py -- --root .
```

Текущая камера этого инструмента воспроизводит прежние серверные картинки, но не является обязательным шаблоном будущих обложек: их следует сначала калибровать по стандартным изображениям игры.

Тест каталога проверяет 13 товаров, отсутствие лишних линеек, прежние товары/их порядок, GUID/fileID/физику, prefab-only состав, сокеты, питание, охлаждение, одну PCOS, обычную RAM/HDD и точные цены, штатный спрайт кулера, пять ящиков, неактивность содержимого до вскрытия, защиту от обломков через штатный ReadyBuildBox, высоту выдачи и идемпотентность генератора. Tray-тест исполняет реальный C# код компонентов с минимальными engine doubles, включая разборку и очистку заводских деталей при загрузке.

**Unity Editor здесь недоступен: полная компиляция и Play Mode не выполнялись.** В Unity нужно проверить доставку пустого корпуса и четырёх сборок, падение закрытой коробки, вскрытие молотком на полу, запуск PCOS, ручную установку кулера, снятие/возврат корзин и сохранение/загрузку закрытого ящика и частично разобранной сборки.
