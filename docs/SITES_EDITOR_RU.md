# Сайты игроков: редактор, страницы и общий хостинг

## Согласованная цель всей функции

- Игровые серверы служат хостами сайтов, которые доступны **всем игрокам** через настоящий backend и поиск Oggle.
- Опубликованный сайт остаётся доступен после выхода владельца из игры.
- Оплата по **реальному времени**, срок идёт и вне игры. Тариф, выбранный с разрешения пользователя: **$100 за 30 реальных минут**, включая офлайн; первый период авансом.
- Пользовательский игровой URL — доплата **$1000**. Это не регистрация настоящего интернет-домена.
- Редактор визуальный, как холст Scratch; обработчики — текстовый Lua, не блочный редактор программирования.
- Button / Text / Image, правый инспектор (имя, координаты, размер, pivot, оформление, текст, шрифт, OnClick), удержание текста для ввода.
- В пакете название, описание, ключевые слова, иконка и все импортированные файлы из виртуального корня сайта. Браузер рендерит свой формат, не HTML. Получение сайта должно учитывать реальную загрузку и игровой интернет.

## Что сделано в этом этапе

В App Downloader добавлен **Site Editor / Редактор сайтов**, ассоциация `.osite`. Из Text Editor переиспользовано только нативное оформление окна и существующая иконка; сам Text Editor и его префаб не изменены. **Весь интерфейс редактора сериализован в `Assets/Resources/apps/SiteEditor.prefab`**: сверху New/Open/Save/Undo/Redo/Preview/Browser/Host, слева Hierarchy, по центру холст, справа прокручиваемый инспектор. Все поля свойств, меню Add, шаблоны строк Hierarchy/действий, Dropdown команд, поле аргументов, кнопки, подписи, прокрутка, маски, контекстные секции, панели настроек сайта/элемента/превью и события кнопок доступны в Unity до Play Mode. Скрипт не создаёт оболочку редактора через new GameObject / SiteWidgets; строки существующих элементов и действий клонируются из сериализованного шаблона Button. Генератор `tools/build_site_editor_ui.py`, вызываемый `tools/wire_site_editor.py`, работает только офлайн, не при запуске игры. Не запускать его поверх ручных изменений префаба без необходимости: штатная игра не перегенерирует макет.

- Создание, выделение, перетаскивание, удаление Button/Text/Image.
- Имя, ID, X/Y, ширина/высота, pivot X/Y у каждого элемента, пресеты top-left/center. Координаты и pivot заданы от верхнего левого угла страницы; (0,0) — top-left, (.5,.5) — center. Позиция обозначает точку pivot.
- Текст, цвет, размер и три стандартных шрифта (Roboto, Roboto Medium, моноширинный из существующих ресурсов проекта). Для button/image — цвет заливки или импортированная PNG/JPEG/PIC-картинка. Цвет вводится в HEX `#RRGGBB` или `#RRGGBBAA`.
- Удержание текста 0.55 сек. включает inline InputField на самом холсте. Drag сохраняется как одна операция undo.
- Настройки проекта: title/description/keywords, размер страницы, фон, импорт иконки и управление файлами корня. Импортированные данные находятся внутри `.osite`, внешние пути не сохраняются.
- Сохранение и открытие в редакторе через штатные PCOS-диалоги. Файл использует существующий механизм хранения/сохранения игры. New требует повторного нажатия, если проект непустой.
- Транзакционный Undo/Redo: недопустимые изменения отклоняются без порчи проекта. Общий бюджет истории — 16 MiB, до 40 снимков.
- Preview использует копию документа: Lua не изменяет авторский проект; переходы на страницы `/about` работают в preview, внешние переходы и скачивания только показываются в строке состояния.

**Host открывает отдельную панель публикации и статистики** с показом тарифа перед подтверждением. Реализованы PHP API общего хостинга, клиент публикации, поиск/открытие сайтов в Oggle, посетители и онлайн. Доступность этой функции в выпущенной игре требует загрузки `Hosting/sites` на Byethost и сборки новой версии клиента; локальные тесты не подтверждают развёртывание.

## Последние правки: Hierarchy, Add и локальный браузер

- Слева **Hierarchy существующих элементов**, а не кнопки создания. Выбор строки выделяет элемент на холсте и открывает инспектор; имя и тип обновляются после добавления/изменения/удаления и Undo/Redo.
- **Add +** открывает выпадающее меню Button / Text / Image. Меню и скрытый шаблон строк находятся в префабе.
- Растровые изображения в элементах растягиваются до заданных width/height: `preserveAspect = false`, в том числе после `SetImage`/`SetSize`.
- В инспекторе Button область действий разделена поровну: слева нативный Dropdown команд и подсказка порядка аргументов, справа поле Arguments. Список сохранённых действий ниже, advanced Lua отдельно.
- **Browser** сверху сохраняет проект и открывает его в игровом Browser. У нового проекта сначала появляется SaveDialog; отказ не открывает несохранённый сайт. Если на диске недостаточно места, старое содержимое не выдаётся за успешную запись.
- Двойной клик `.osite` в проводнике открывает Browser. Для редактирования — Open внутри Site Editor либо «Открыть с помощью» Site Editor. При передаче документа редактор запоминает путь/диск.
- Адресная строка: `file://disk/123/Sites/MySite.osite`. Это виртуальный адрес **диска PCOS**, не файловая система устройства игрока. 123 — ID накопителя, а не индекс диска, пробелы/Unicode кодируются URL-encoding. Ручной ввод такого адреса загружает файл с соответствующего диска. Ссылки на защищённый System, traversal и чужие схемы не обрабатываются как локальный сайт.
- После `OpenFile("test.txt")`: `file://disk/123/Sites/MySite.osite#site/test.txt`. Изменение строки обратно на адрес без `#site/...` возвращает страницу. Подфайлы всегда читаются из пакета `.osite`, не из соседней папки и не с устройства посетителя.
- Для локального файла интернет не требуется. `RedirectURL` на игровой домен использует обычный Browser.Search и существующие проверки/симуляцию интернета. Навигация из обработчика откладывается до следующего кадра, чтобы не уничтожать выполняющийся холст; смена страницы/закрытие/остановка системы отменяет устаревший переход.

## Исправление размера окна по скриншоту пользователя

Прежний фиксированный корень 1000 x 680 выходил за область PCOS; верхние кнопки и нижняя часть скрывались. Базовый размер префаба теперь 900 x 560. В Open подгоняется только корневое окно: по RectTransform родителя, в локальных единицах игрового монитора, с GetTaskbarInsetLocalHeight и полями 8 единиц. Screen.width/height и принудительная смена localScale не используются. Внутренние панели растянуты anchors: Hierarchy 18%, холст 54%, инспектор 28%. Toolbar/статус имеют отдельные верхний/нижний отступы и не перекрывают workspace.

При смене разрешения родителя окно подгоняется повторно; при обычном кадре/перетаскивании не центрируется заново. Maximize оставлен штатному App, с его отступом над панелью задач; после восстановления размер вновь ограничивается рабочей областью. Инспектор прокручивается, а его поля не пересоздаются при выделении/вводе; значения обновляются через SetTextWithoutNotify. После последней доработки корневые файлы показаны отдельными строками с иконками и кнопками удаления.

`python tools/test_site_editor_layout.py`: 775 проверок настоящего C# расчёта/методов подгонки с API doubles, включая 320–1920 по ширине, несколько высот и taskbar inset, смену размера родителя, отсутствие постоянного центрирования, восстановление после Maximize. Также проверяются сериализованные поля, кнопки/методы, панели, отступы и маски. Это не визуальная проверка в Unity.

## Доработка по изменённому пользователем интерфейсу (после `1c8694c`)

Изменения основаны на пользовательском префабе `1c8694c`, а не на повторной генерации старого окна. `tools/upgrade_site_inspector.py` меняет инспектор и строки файлов **на месте**; сохраняет существующие размеры/позиции toolbar, canvas, hierarchy и оставшихся настроек сайта. Обычный запуск `wire_site_editor.py` теперь не сбрасывает пользовательское окно. Полная пересборка возможна только с явным `--rebuild-shell`.

### Импорт программ

Прежняя ASCII-проверка имён запрещала пробелы, поэтому, например, `Device Manager.exe` не попадал в корень. Кроме того, штатные PCOS-программы могут быть пустыми `.exe`-маркерами, а прежняя проверка отвергала нулевую длину. Теперь:
- Разрешены обычные корневые имена с пробелами, Unicode и скобками; по-прежнему запрещены разделители пути, управляющие символы, `:`, `"`, `<`, `>`, `|`, `?`, `*`, имена `.`/`..` и пробелы по краям.
- Разрешены пустые игровые файлы `application/x-pcos-file`, **но не пустые изображения**. Программа-маркер остаётся программой-маркером: импорт не создаёт настоящий бинарник устройства игрока и не добавляет отсутствующее приложение в каталог игры.
- При повторном импорте создаются `My Program (2).exe`, `(3)` и т.д., существующая версия не затирается. Остаются ограничения пакета/размеров и запрет автоматического запуска.

### Контекстный инспектор и оформление

- Для Text видны текст, шрифт, стиль и цвет текста; нет заливки, импорта картинки и OnClick. Для Image — геометрия/заливка/изображение, без текстовых настроек. Для Button — поддерживаемые текстовые настройки, заливка и действия. Секции действительно скрываются и список перестраивается без пустых промежутков, а не просто блокируются поля ввода.
- У Image есть **Enable OnClick → Button**: тип меняется на button, картинка остаётся fill image, геометрия/имя/оформление сохраняются, подпись очищается. Операция участвует в Undo/Redo.
- Шрифт выбирается Dropdown: Default / Monospace / Medium. **B, I, U, S** переключают жирный, курсив, подчёркивание и зачёркивание. Глифы самих кнопок показывают соответствующее начертание. B/I используют FontStyle, U/S — отдельные mesh-линии, не исполнение пользовательских rich-text-тегов. Оформление сериализуется в `.osite`, рендерится на холсте, в preview и Browser.
- Обычные надписи редактора переведены на отдельный Regular font asset с уникальным GUID: в исходных ресурсах несколько Roboto-шрифтов имели один GUID, что могло давать непредсказуемое начертание. Жирным/курсивом остаются только демонстрационные буквы кнопок B/I и явно оформленный пользователем текст сайта. Остальные программы игры не менялись.
- Рядом с HEX-цветом текста/заливки/фона есть **Color…**: используется тот же сериализованный RGB/HEX ColorPicker, что в Paint, с предпросмотром и Set/Cancel. Ручной HEX-ввод сохранён; аргументы `color` команд также имеют кнопку выбора.
- Site root files — строки с системной иконкой **по расширению**, полным именем, размером содержимого и отдельным **×**. Для `.pic` используется штатная файловая иконка Viewer. Поиск иконки не читает совпавший файл с диска посетителя. Удаление убирает прямые ссылки image/icon; действия со ссылкой на удалённый файл не переназначаются молча — их нужно исправить/удалить.

### Pivot / anchors

Dropdown содержит Custom, девять точек (3×3), три горизонтальных stretch, три вертикальных stretch и полный Stretch all. Custom оставляет ручные X/Y pivot. Важно: pivot — опорная точка элемента, anchors/stretch — привязка его положения и размера к странице; это не одно и то же.

При выборе пресета сохраняются видимые границы элемента, а размеры страницы запоминаются как опорные. При изменении размера страницы anchors перемещают/растягивают элемент относительно этой опоры. У страниц с anchor-пресетами Browser использует реальную ширину своего viewport, так что Stretch all заполняет страницу, Center остаётся по центру и т.д.; для старых страниц целиком на Custom сохранено прежнее пропорциональное вписывание. Высота страницы по-прежнему задаётся проектом и прокручивается. Для адаптивного сайта нужно назначить нужные пресеты всем соответствующим элементам, а не только фону.

### Аргументы команд

Справа от команды теперь до трёх отдельных подписанных контролов, а не один текстовый блок с позиционными строками:
- `file`: Dropdown файлов проекта; у SetImage — только импортированные изображения.
- `id`: Dropdown с именем, типом и стабильным ID подходящего элемента. SetText/шрифт/цвет текста не предлагают Image, оформление картинки не предлагает Text, Enabled предлагает Button.
- `font`: Dropdown шрифтов; boolean — true/false.
- Числа/свободный текст/URL — отдельные InputField. Например, **SetText → Download [button] → новый текст**. Цвет — HEX + ColorPicker.

Значения сохраняются как строки данных, не как подставляемый исполняемый Lua. Списки обновляются после изменения проекта; удалённая или неподдерживаемая цель показывается Missing / unsupported. Add/Update не позволяют принять такую цель. Advanced Lua остаётся отдельным полем для выражений/переменных; строки там по-прежнему требуют Lua-кавычек.

## Хостинг: уточнение пользователя

Для хранения пакетов выбран **основной бесплатный Byethost**, а не новый платный внешний сервис. Переданные реквизиты в код, префабы, документацию, тесты и git не записываются. Новая серверная часть сайтов в этом изменении не развёртывалась; существующие адреса Workshop/аккаунтов не переключались. Домен/каталог API сайтов ещё должны быть подтверждены перед подключением клиента. Игровая стоимость хостинга и доплата за игровой URL — отдельная внутриигровая экономика, не плата Byethost.

## Формат и ограничения первой версии

JSON `format: "orange-site"`, `version: 1`; элемент имеет стабильный ID, kind (`button`, `text`, `image`), геометрию, оформление, текст, массив структурированных actions и необязательный onClick (advanced Lua). assets — плоский виртуальный корень с `name`, MIME/media, base64 data. Это не Unity prefab и не сериализация произвольных CLR-типов.

- Пакет до 8 MiB UTF-8, глубина JSON до 32, до 256 элементов, до 64 файлов.
- Файл до 2 MiB, суммарно до 6 MiB декодированных данных; картинки до 2048 x 2048 и суммарно до 8 мегапикселей. До LoadImage проверяется заголовок/размер, после — успешное декодирование. Эти технические предохранители не являются согласованными тарифами/лимитами серверного железа.
- Имена файлов только в корне; без разделителей `/`, `\\`, имён `.`/`..`, URL и абсолютных путей; пробелы и Unicode разрешены. MIME whitelist: PNG/JPEG и `application/x-pcos-file` (содержимое **игрового** файла). Исполнять скачанный файл автоматически запрещено.
- Пакет проверяется при чтении, записи, изменениях и перед рендером. Текст не обрабатывается как rich text или HTML. Нет внешних шрифтов и изображений.

## Lua сайта

Пример OnClick:

```lua
RedirectURL("www.modforge.com")
```

Другой обработчик:

```lua
SetText("heading", "Готово!")
Alert(GetText("heading"))
StartDownload("site/myapp.exe")
```

Общий каталог содержит **34 команды**, одинаковые для Dropdown и отдельного Lua сайта:

- Переходы/файлы: `RedirectURL(url)`, `OpenFile(file)`, `StartDownload(file)`, `FileExists(file)`.
- Текст: `SetText(id,text)`, `AppendText(id,text)`, `ClearText(id)`, `GetText(id)`, `SetTextColor(id,color)`, `SetFontSize(id,size)`, `SetFont(id,font)`.
- Геометрия: `SetPosition(id,x,y)`, `MoveBy(id,dx,dy)`, `SetSize(id,width,height)`, `SetPivot(id,x,y)`, `GetX(id)`, `GetY(id)`, `GetWidth(id)`, `GetHeight(id)`.
- Оформление: `SetFillColor(id,color)`, `SetImage(id,file)`, `ClearImage(id)`, `SetBackground(color)`.
- Состояние: `Show(id)`, `Hide(id)`, `ToggleVisible(id)`, `SetVisible(id,visible)`, `IsVisible(id)`, `SetEnabled(id,enabled)`, `IsEnabled(id)`.
- Метаданные/сообщения: `GetTitle()`, `GetDescription()`, `GetURL()`, `Alert(text)`.

В advanced Lua аргументы-строки требуют кавычек; в обычном инспекторе — отдельные поля/Dropdown аргументов с данными, без Lua-кавычек. Числа с точкой, логические значения `true`/`false`. Для `OpenFile` выбирается `test.txt` из списка (в Lua также принимается `site/test.txt`). Для `SetText` выбирается элемент и вводится новый текст в отдельное поле. Add action добавляет, Update меняет выбранную строку, Remove удаляет. Геттеры в списке действий показывают результат сообщением; в Lua их можно использовать в выражениях. Сначала выполняются actions, затем advanced Lua; общий бюджет 32 вызова API на клик, не 32 на каждый режим отдельно. Старые файлы без actions остаются совместимыми.

Ссылка — только адрес внутри игрового браузера, не настоящий HTTP-запрос и не запуск внешнего браузера. `OpenFile` открывает **только импортированный корневой файл пакета**: текст (txt/md/json/csv/lua/html/css/log, без исполнения HTML/Lua) либо изображение. Текстовое превью ограничено 32768 символами. Другие типы нужно скачивать через `StartDownload`; автозапуска нет. Download использует подтверждаемый штатный SaveDialog с обычными правами даже у браузера, открытого администратором. Ни одна из команд не получает доступ к произвольным дискам посетителя или System.

Используется существующий PcosLua, но **не вызываются PcosLuaHost.Bind/LuaUi/LuaGfx**. Нет API `os`, `fs`, `admin`, `pc`, `terminal`, `io`, `require` и сетевого API. Удалены потенциально дорогие стандартные `string`, `table`, `pcall` из VM сайтов. На обработчик: 256 токенов, 5000 операций, глубина вызовов 32, строки конкатенации до 8192, до 32 UI/навигационных действий. Обработчики запускаются только по клику; нет autoplay/update.

В общем интерпретаторе добавлены необязательные лимиты, значения прежних приложений не изменены. Заодно переменная библиотеки table переименована без смены логики: прежнее имя конфликтовало с локальными переменными лямбд при компиляции Mono.

## Переходы между страницами одного сайта

1. Создать страницу `/about` через поле пути и кнопку `+ page`.
2. Выбрать кнопку на холсте → OnClick → команда **GoToPage**.
3. В аргументе **page** выбрать `/about` из списка → Add action / Update.
4. Для возврата на главную выбрать `/`. В текстовом Lua: `GoToPage("/about")`.

Все вкладки одного `.osite` публикуются одним пакетом на **одном домене**:
`tux.com/`, `tux.com/about`, `tux.com/about/team`. Отдельный Host для каждой
страницы не нужен; доплаты за домен/аренды на каждую страницу нет. Команда
GoToPage принимает только внутренний путь, не внешний домен; RedirectURL
остаётся для внешних адресов и совместимости со старыми проектами.

## Остановка и смена домена

Прежнее ограничение `Published URL is immutable` **убрано**. В панели Host поле
URL остаётся редактируемым. Ввести новый домен → Publish: обновляется та же
публикация с теми же ID, ключом проекта, страницами, файлами и счётчиком визитов.
Старый адрес перестаёт работать, новый обслуживает все прежние пути `/about`.
Период уже оплаченной аренды при смене активного сайта не сбрасывается.
+$1000 берётся за каждый 30-минутный период собственного домена;
последующие смены не требуют доплаты. Ранее опубликованные собственные домены
автоматически считаются оплаченными. Пустое поле оставляет текущий адрес.
Занятые и системные адреса по-прежнему запрещены.

Stop выбирает сайт в списке (при открытии панели по умолчанию текущий проект),
дожидается фонового запроса, отправляет остановку и показывает подтверждение.
Панель больше не возвращает пустой список раньше завершения stats и не
перетирает остановку запоздалым ответом active=true. Фоновые изменения
автоматически отображаются, набираемый домен при этом не теряется. Отложенная
публикация, ещё находящаяся в диалоге сохранения/симуляции передачи, отменяется
нажатием Stop и не включает сайт обратно. Для возобновления нужно явно Publish.

После подтверждения Stop API сразу исключает сайт из поиска и отказывает в
view/visit; онлайн обнуляется, следующего списания нет. Ранее начисленный долг
сохраняется. Открытая страница владельца скрывается при следующем кадре с
обновлённой статистикой; у остальных посетителей — на следующем heartbeat
(обычно до 20 секунд плюс время ответа сети). Результаты поиска обновляются
каждые 20 секунд и удаляют недоступные пользовательские сайты. Остановка и
смена домена отзывают старые visitor tickets, в том числе после возобновления.

Дополнительно `tools/test_site_pages.py` выполняет асинхронные тесты жизненного
цикла с отложенными callback: открытие панели во время stats, очередь Stop,
остановка выбранного проекта, обновление домена без смены ключа, защита от
устаревшей статистики/смены аккаунта и явные ошибки связи. Тест PHP проверяет
остановку, отсутствие начислений в остановленном состоянии, отзыв старых
сессий, смену домена, сохранность страниц/счётчика и однократную доплату.

## История, иконки, переименование, скачивания, оплата и модерация

- История/избранное открывают адрес через тот же `Search`, что и адресная строка,
  включая пользовательские домены и `/about`. Ошибка «пока недоступен в Oggle»
  больше не выдаётся только из-за отсутствия встроенного Website prefab.
- Oggle показывает title сайта вместо домена; домен остаётся в описании.
  `OggleResultItem.icon` ссылается на добавленную автором RawImage. Встроенные
  сайты используют Website.websiteName/icon, пользовательские — метаданные API.
  История получает title и иконку через лёгкий `info`, без загрузки всего пакета.
  Сервер делает миниатюру до 96px с GD; без GD принимает уже небольшую иконку
  до 256px/64KiB, иначе клиент показывает стандартную. Текстуры освобождаются
  при закрытии Browser; пиксели/заголовки не исполняются как HTML.
- Выбрать вкладку, ввести новый путь и нажать **Rename**. Главная остаётся `/`.
  Все структурированные GoToPage/RedirectURL на точный старый путь обновляются;
  в Lua обновляются прямые строковые вызовы этих команд. Вычисляемые пути через
  переменные нужно проверить вручную. Undo возвращает путь и ссылки вместе.
- StartDownload удалённого сайта сначала проверяет ticket/существование файла,
  потом ждёт реальное время. Длительность — минимум по пропускной способности
  хост-ПК/его тарифу, CPU Score/троттлингу, CPU load/онлайн и интернету посетителя
  (его тариф, сигнал, трафик). Прогресс отменяется при навигации, выключении,
  обрыве связи; перед SaveDialog повторно проверяются оплата/бан/остановка.
  Файлы остаются частью собственного `.osite`, не выполняются автоматически.
  Это симуляция передачи в игре; не отдельный исполняемый HTTP-файл на Byethost.
- Общий игровой баланс передаётся backend вместе с уже оплаченным итогом по
  данному аккаунту/сохранению. Сервер хранит лимит `settled + balance`, общий
  для всех сайтов этого сохранения, и расходует его офлайн. При невозможности
  оплатить очередные $100 период не начинается: сайт показывает **«Хост не
  оплачен»**, онлайн сбрасывается, пакет/скачивания не выдаются. Уже оплаченный
  период дорабатывает до конца. За время неоплаты новый долг не растёт;
  после нового достаточного снимка баланса начинается новый оплаченный период.
  Локальные деньги/журнал по-прежнему сводятся с серверным итогом при соединении.
  Это последний известный баланс, а не доверенная серверная экономика: пока
  владелец офлайн, сервер не может видеть последующее изменение файла сейва.
  Долги, начисленные до введения снимков, не аннулируются автоматически.
- В `/workshop/admin.php?tab=sites` появилась вкладка **Сайты игроков**: домен,
  заголовок, владелец, состояние, визиты/онлайн/счёт, визуальные страницы и галерея изображений. Бан/разбан защищены существующей админ-сессией и CSRF.

  аренду. Смена домена не обходит бан той же публикации. Разбан не включает

CPU: пассивное охлаждение голого процессора уменьшено до уровня теплоотдачи
крышки, а не полноценного радиатора. Убрана выдача чужого кулера через поиск
всего поддерева корпуса/платы. Троттлинг остаётся, но без кулера под нагрузкой

## Уточнение: Server.exe, выключение хоста и визуальная модерация

Актуальный тариф: **$100 / 1800 секунд + $1000 / 1800 секунд за свой домен**.
Стандартный `s<ID>.sites.pcos` остаётся без доменной доплаты. Обновление активной
публикации не оплачивает период повторно. После Stop/неоплаты нужен новый период
($1100 со своим доменом). Старым записям не повышаются уже прошедшие начисления;
новый тариф применяется со следующей границы периода после обновления backend.

Скачивания в Browser открывают **тот же ProgressBar, что и App Downloader**,
с процентом и Cancel. Страница не заменяется загрузочным экраном. Время зависит
от тарифа посетителя, пропускной способности/CPU/load/онлайна хоста; минимальный
видимый интервал — 1 секунда. `start/pulse/end/cancel` передаются backend,
активность истекает через 30 секунд без pulse, ticket продлевается каждые 10 секунд.
Перед SaveDialog снова проверяются доступ/бан/оплата. Сам App Downloader не изменён.

Когда на ПК есть оплаченная активная публикация, в Task Manager появляется
**Server.exe** (один на ПК, не по процессу на страницу). Он резервирует половину
исправной установленной RAM. Дополнительно учитываются онлайн-посетители
(4 MB каждый), скачивания (16 MB каждое) и короткие скачивания между опросами.
Это прибавляется к настоящему расчёту RamUsedMb/RamLoad ОС, а CPU demand — к
Workload процессоров, то есть влияет на нагрев, троттлинг и отзывчивость ОС.
CPU: база 20 единиц/сайт, 35/онлайн-посетителя, 120/передачу плюс интенсивность
посещений/недавних скачиваний. Статистика обновляется раз в 5 секунд при наличии
связи; это симуляция ресурсов в загруженном сейве, не исполняемый сайт на Byethost.
Снятие Server.exe останавливает публикации этого ПК и освобождает резерв.

PowerOff/ForceDown (включая сгоревший CPU/питание) и BSOD отправляют авторизованный
`host_stop`: останавливаются только публикации owner/world/host этого ПК.
Новые начисления прекращаются, tickets отзываются. Состояние локально выключается
сразу, записи об остановленных хостах повторяются в запросах stats при сетевой
ошибке. Само закрытие сейва/выход в меню/рестарт сцены не отправляют остановку.
На новом старте остановленная публикация требует явного Publish.

В админке **Посмотреть сайт** открывает изолированный iframe: цвета, геометрия,
текст, фон, изображения и кнопки прямых переходов; страницы выбираются сверху.
Ниже — галерея картинок с раскрытием полного размера. Данные не вставляются как
HTML, произвольный пользовательский Lua не исполняется; сложные Lua-сценарии
проверяются в игровом Browser. Это визуальный предпросмотр формата orange-site,
не идентичный Unity рендереру движок шрифтов. Вкладка обёрнута в обычную белую
карточку админки; пояснения о смене домена и о бане со скриншотов удалены.
