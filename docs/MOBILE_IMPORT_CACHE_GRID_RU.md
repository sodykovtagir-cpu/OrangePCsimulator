# Мобильный импорт, постоянный кеш списка сейвов и единая сетка HUD

## Paint / Animator

- Работающий импорт GIF уже использовал NativeFilePicker. Paint.OpenLocalFile и Animator.PickVideoFromDevice использовали NativeGallery, чей GetMediaFromGallery сначала вызывает RequestPermissionAsync(Read, mediaType). Это отдельный путь с разрешениями, а не уже настроенный permission-free SAF NativeFilePicker.
- Эти два импорта переведены на существующий NativeFilePicker: PNG/JPEG для Paint, video/* для Animator. Сам импорт GIF не изменён. Плагин/AAR/manifest не заменялись.
- Отмена выбора и запоздавший callback после закрытия приложения не запускают импорт. Есть обработка исключений/недоступного локального файла и сообщения об ошибках.
- Paint проверяет успешный LoadImage, не уничтожает прежний рисунок при ошибке декодирования/resize. Новая текстура становится текущей только после успешной обработки. Размер исходного файла ограничен 32 МиБ.
- Resize Paint сохраняет прежний RenderTexture.active и освобождает temporary RT через finally, включая ошибки ReadPixels.
- Animator передаёт VideoPlayer корректно экранированный абсолютный file URI (пробелы, #, Unicode). Лимиты 8 FPS / 96 кадров и прежний прогресс/cleanup сохранены. Поддержка кодека остаётся зависимой от устройства: выбор файла не гарантирует, что любой MKV/HEVC будет декодирован.

Это исправление маршрута импорта; реальный Android-диалог и декодер видео в этой среде не запускались.

## Почему список появлялся позже

Раньше SaveCatalog держал заголовки только в RAM, а FileMenu при каждом открытии очищал/удалял строки и ждал IsScanning == false. Получалось пустое окно даже при наличии старого снимка списка. Texture-кеш обложек сам по себе этого не устранял.

Теперь:

1. После успешной индексации сохраняется компактный `.menu-index-v1.cache` в папке сейвов: имя файла, размер/mtime, название мира, hardcore, отметка публикации и данные обложки. Монеты, ключи workshop, полный второй мир, PCOS/site/Lua-состояния туда не копируются.
2. При следующем запуске этот ограниченный индекс публикуется в BeforeSplashScreen до запуска фоновой проверки `.opc`. Обложки доступны для уже существующего прогрева SaveCoverCache.
3. FileMenu сначала показывает текущий RAM/дисковый снимок, не ждёт полного сканирования и не уничтожает уже показанные строки. Неизменившиеся строки и Texture2D переиспользуются; обновления/добавления идут с прежним бюджетом до 8 строк / 3 мс.
4. После фоновой проверки обновляются изменённые строки, а исчезнувшие/нечитаемые удаляются. Состояние «нет сейвов» не показывается во время ожидания сканера.
5. Неизменённое обновление не переписывает дисковый индекс. Запись индекса через отдельный temporary-файл с Flush(true) и заменой; переносимый fallback сохраняет предыдущий индекс. Это не транзакция `.opc`: сохранения и их `.bak/.pending` не затрагиваются.
6. Повреждённый/неподдерживаемый кеш игнорируется; имена в нём не могут выходить из папки сейвов. Пределы: 4096 строк, файл до 12 МиБ, до 64 закешированных обложек с суммарной строковой квотой 4 МиБ. Существующий GPU/RAM-кеш текстур ограничен 8 МиБ. Полный актуальный список после проверки не ограничивается этими 4096 строками.

### Кеш — только для отображения

DataLoader.FromPreview создаёт IsPreviewOnly-загрузчик. WriteToFile для него запрещён: неполные поля заголовка нельзя случайно записать поверх настоящего мира. Перед открытием редактирования FileMenu на worker заново читает настоящий подписанный заголовок. Открытие игры всегда использует настоящий файл; чтение Content из preview также выполняет полную загрузку. Подмена отображаемых монет/полей в кеше не становится состоянием игры.

После установки этого обновления индекс должен один раз построиться: у предыдущей версии дискового индекса не существовало. Нельзя обещать мгновенный полный список при первом запуске без кеша, после его очистки/повреждения или после очистки данных приложения. После построения он сохраняется между запусками; даже тогда реальный мир проверяется отдельно.

OPC3/HMAC, исправление большого заголовка, импорт сейвов и восстановление pending/bak сохранены без изменения алгоритма.

## Стрелки Grid на Large / Double Storey

Пользователь уточнил: отличаются размер и расположение стрелок, а не иконка Grid.

Раньше UiScale один раз рассчитывался от текущих Screen.width/height и DPI, хотя игровой HUD всех четырёх карт использует CanvasScaler Expand 800×500. Если разрешение рендера менялось после создания UI, физические пиксели и логические единицы смешивались; сохранённый offset мог сочетаться с уже другим размером панели.

- Масштаб теперь считается в логических Expand-единицах, одинаково для игры и превью. Для обычного landscape это 0.85, панель 340 логических единиц — соответствующий присланному Factory ориентир на скриншоте 1568×706. DPI и 35–100% render resolution больше не меняют размер кнопок в единицах HUD.
- Поиск Canvas в первую очередь использует ControlRig.mobile, а не случайный первый overlay. Создание откладывается, если область ещё нулевая/scaleFactor неположительный.
- Обработчики стрелок, удержание, мелкий шаг, переключатель «Движ./Поворот», ключ GridArrows и сохранённые якоря не изменены. Физика сетки и сцены не переписаны.

Это устранение зависимостей от размеров/порядка инициализации; точное воспроизведение различия двух APK-карт без устройства не подтверждено. Нужна визуальная проверка в реальной сборке.

## Боковой хотбар и деньги

MobileAdaptiveSlidePanel резервирует сверху 60 логических единиц, когда находится слева/справа. Это полоса существующего HUD с деньгами/«+» (у всех четырёх карт одинаковое размещение). Она учитывается и в fit-масштабе, и в ограничении всех углов/позиций, а не исправляется только сдвигом уже слишком длинной панели. Превью использует то же правило. Обычный отступ 8 единиц сохранён; верхняя/нижняя горизонтальная ориентация не менялась.

## Проверки

Успешно:
- 16 проверок с компиляцией фактических методов Paint и видео-picker Animator: фильтры, успех/отмена, lifecycle, недоступный/плохой файл, сохранность прежнего рисунка, RT cleanup, URI.
- 18 проверок постоянного кеша на реальных SaveCatalog/DataLoader и отдельных процессах. Worker намеренно удерживается lock'ом: список и данные обложек уже доступны до чтения сейвов. Также проверены запрет записи preview, повторная аутентификация, сохранность полного мира/заголовка при редактировании, недоверие cached balance, удаление, повреждённый кеш и отсутствие лишней перезаписи индекса.
- 13 проверок реальных menu-coroutine: кешированные строки при активном сканере, переиспользование строк/текстур, bounded batching, отмена, worker-open.
- 24 проверки реального UiScale на разных DPI/разрешениях и проверка одинаковых CanvasScaler всех четырёх сцен.
- 3915 проверок реальной геометрии бокового хотбара на TRS/UI-дублях, включая верхнюю полосу под деньги.
- Регрессии: startup/durability 15 + 4 restart, OPC2/OPC3/большие заголовки, экспорт, screenshot state (28), grid/mobile/layout/icon, Animator prefab, Save As prefab, Android picker JNI (7), desktop picker Win/Mac/Linux, Android Open with, resolution (29), blur integration (63), движение (14), 4 shader passes и boot.

Дополнительный старый `test_save_as_runtime.py` не компилируется из-за устаревших собственных doubles (нет JsonUtility и Storage.Id для уже существующего SaveDialog). SaveDialog и этот тест данным изменением не менялись; это не выдаётся за успешную проверку. Отдельный актуальный статический test_save_as_picker и тест настоящего экспорта проходят.

Нет Unity Editor/APK/реального телефона и замера FPS. Native GUI и аппаратный VideoPlayer не проверены. Ручной чек-лист:
1. Без разрешения на всю медиатеку импортировать PNG/JPEG в Paint; отмена/битый файл должны сохранить рисунок.
2. В Animator импортировать короткий MP4 H.264, включая имя с пробелами/#/кириллицей; проверить кадры/100%/отмену. Повторить рабочий GIF.
3. Дождаться первого построения кеша, закрыть/перезапустить приложение, сразу открыть сейвы: должны быть кешированные строки/обложки, без предварительного ложного «пусто». Проверить импорт, переименование/удаление и редактирование до завершения проверки.
4. На одном устройстве/настройке открыть Factory, Large и Double Storey: стрелки должны иметь общий масштаб/позицию. Повторить на 35% и 100% разрешения.
5. Поставить хотбар слева/справа и в оба верхних угла: он не должен закрывать деньги/«+»; сохранить раскладку, перейти в другую карту.
