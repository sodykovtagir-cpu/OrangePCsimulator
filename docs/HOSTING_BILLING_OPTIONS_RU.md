# Хостинг сайтов: как работает, за что платит игрок

**Итоговая модель (пересмотрена 2026-11-16, вариант «кошелёк + трафик»):**

| Что | Сколько | Откуда берутся деньги |
| --- | --- | --- |
| Публикация сайта | $0 | — |
| Аренда за работу сайта | $100 / 30 мин (свой домен — $1100 / 30 мин) | кошелёк хостинга |
| Трафик (реальное обслуживание) | $20 / 30 мин, только пока на сайте есть открытая сессия или скачивание | кошелёк хостинга |
| Свой домен | $1000 один раз | кошелёк хостинга |
| Пополнение кошелька | шаг $100 | игровой баланс, **только по кнопке** |

Деньги игры никогда не списываются фоновым запросом: синхронизация только читает состояние. Именно поэтому игра больше не подвисает (раньше каждый ответ сервера мог вызвать `SaveData()`).

Без связи игра сама переходит в локальный режим: показывает последнее известное состояние, считает обслуживание локальных сайтов и повторяет попытки с паузой 60 → 120 → 240 с. Опубликовать новый домен без интернета нельзя, хостить сайт из сохранения — можно.

Ниже — исходный разбор старых вариантов и почему выбран этот.

## 1. Как система устроена сейчас (факты по коду)

### Клиент (Unity, C#)

`Assets/Scripts/Assembly-CSharp/PC/Component/Software/Sites/SiteHostingService.cs`

- `Stats`-поллинг каждые 5 секунд, пока игрок в мире и залогинен (`Refresh` → `nextPoll = now + 5`).
- В каждом запросе отправляется:
  - `world` — GUID сохранения (`GameData.siteHostingWorld`, создаётся при первом обращении);
  - `balance` — `Main.Instance.Money` целиком, на весь общий баланс игрока;
  - `ledgers` (или `settled`) — журнал `GameData.siteHostingLedger`: сколько **уже списано** по этому аккаунту;
  - `hosts` — профили CPU/RAM/Mbps каждого хост-ПК;
  - `stopped_hosts` — хосты, которые игрок выключил.
- Списание делается локально в `ApplyCore`:

  ```csharp
  long due = reply.total - ledger.charged;   // total — суммарный счёт сервера
  if (due <= 0) return;                      // ← возврата переплаты НЕТ
  Main.Instance.SetMoney((int)(money - due), true);
  ledger.charged = reply.total;              // затем SaveData()
  ```

  Если `SaveData()` упал — деньги и журнал откатываются, списание повторится при следующем соединении.
- Деньги могут уходить в минус (явно разрешено в `docs/SITES_EDITOR_RU.md`).

### Сервер (PHP, Byethost, `Hosting/sites/`)

- `state.php` — один base64-JSON файл под `flock`, все запросы читают/пишут его целиком.
- Тариф: `SITE_PRICE = 100` за `SITE_PERIOD = 1800` секунд, `SITE_CUSTOM_PRICE = 1000` за свой домен. Первый период — вперёд при Publish.
- `site_reconcile($db, $now)` — начисляет за **все** прошедшие целые периоды от `billed_at` **независимо от того, заходил игрок или нет**:

  ```php
  $n = max(0, intdiv($now - $s['billed_at'], SITE_PERIOD));
  $s['total'] += $n * site_period_price($s);
  ```

- Потолок трат: `site_snapshot()` хранит `wallets[owner:world].ceiling = balance + settled`, присланные **клиентом**. Из этого потолка сервер вычитает начисления. Не хватает денег на период → `unpaid = true` (сайт «Хост не оплачен»: онлайн сбрасывается, пакет и файлы не выдаются, новый долг не растёт).

### Что это значит на практике

| Ситуация | Что происходит |
| --- | --- |
| Играю с интернетом | Каждые 5 с сервер отдаёт `total`, клиент списывает разницу. Списание «пачками» по $100/$1100 на границе периода. |
| Выхожу из игры на 3 дня, сайт активен | Сервер начисляет 86400/1800 = **144 периода**, то есть $14 400 (со своим доменом — $158 400). При следующем входе списывается всё сразу; если денег не хватает — сайт уже `unpaid`, и накопленного долга больше не растёт. |
| Захожу **без интернета** | Запросов нет вообще. Ни начисления, ни списания не видно: сайт выглядит рабочим, деньги не двигаются, `total` не растёт. Расхождение вылезет при первом соединении. |
| Правил сейв / откатил бэкап | `settled` присылает клиент, сервер только проверяет `settled <= total`. Откатил `ledgers` — сервер поднимет потолок заново, деньги можно не заплатить. |
| Переплатил (сервер вернул меньший `total`) | `due <= 0` → просто ничего. Возврата нет. |

### Слабые места, которые стоит починить в любом случае

1. **`due <= 0` не возвращает переплату.** Если локальный журнал «съехал» вперёд (загрузка старого сейва, откат, ручная правка), деньги сгорают молча.
2. **`settled` — доверенное значение от клиента.** Любая потеря журнала = потолок трат заново поднимается за счёт тех же денег.
3. **Скачок на 144 периода.** Нет «пола» и нет понятия «сколько ещё протянем»: игрок узнаёт о катастрофе только когда сайт уже мёртв.
4. **Каждый `stats` переписывает весь `state.php`** (до 200 сайтов, base64-JSON). При 5-секундном поллинге это тяжёлая запись на shared-хостинге.
5. **`ledgers` целиком в каждом запросе** — до 1000 записей в теле каждого stats.
6. **Нет идемпотентности списания:** `total` — единственная истина, а локальная запись «сколько уже заплатил» живёт только в сейве. Сейв и сервер не сверяются по идентификатору транзакции.
7. **Нет представления «осталось времени»**: `next_bill` есть, но нет «денег хватит ещё на N минут».

## 2. Варианты

### Вариант A — «Такси»: посекундная аренда

Сервер начисляет не периодами по $100, а посекундно (тик 60 с), цена за секунду = $100/1800. Клиент списывает накопленное при каждом stats.

- **Плюсы:** цена всегда пропорциональна времени, никаких «сгоревших» 29 минут, никаких скачков на $14k; легко показать «$3,33/мин».
- **Минусы:** очень частые списания (батчить по $5–10), меняется модель «первый период вперёд» на Publish; нужно больше правок на сервере, старые записи надо мигрировать.
- **Оффлайн:** копится, как сейчас, но плавно — «долг» растёт, а не прыгает.

### Вариант B — «Тайм-банк»: предоплата на сервер

Деньги не «списываются по факту», а **кладутся на серверный кошелёк времени**: «Положить $100 на 30 минут» (или сразу $1000). Пока время есть — сайт живёт, в том числе оффлайн. Время кончилось — сайт на **паузе** (публикация, домен и файлы целы, но посетителей не пускает), никакого минуса и никаких долгов.

- **Плюсы:** самая понятная механика («как карта хостинга»), отрицательного баланса не бывает, оффлайн работает честно и без сюрпризов, легко обосновать игроку цифру «осталось 47 минут».
- **Минусы:** нужен игровой магазин пополнения + UI («Положить $»), два баланса (игровой и хостинговый), которые надо свести; нельзя «заплатить позже».

### Вариант C — «Долг с полом»: то, что ты описал, но по-человечески

Оффлайн начисляется, но списание при заходе ограничено: не больше всего баланса (пол 0) плюс «переработка» — сайт может в долг до N периодов (например, 3), после чего пауза. Долг списывается первым же заходом.

- **Плюсы:** минимальные правки к текущему коду, привычная логика «зашёл — заплатил за всё».
- **Минусы:** игрок всё равно видит большой минус при заходе, должник не может «доработать» сайт; жёсткий пол легко превращается в «сайт умер, пока я спал».

### Вариант D — «Плюшки»: терминал хостинга в ОС + журнал

Внутриигровое приложение «Orange Hosting»: минут осталось, деньги, кнопка «Пауза», «Пополнить», история списаний, «сколько хватит при текущем тарифе», предупреждение за 5 минут. Плюс оффлайн-журнал: при заходе без сети видны последние известные цифры и метка «сверка при подключении».

- **Плюсы:** убирает 90 % ощущения «меня обманули»; пригодится в любом из A/B/C.
- **Минусы:** UI-работа, само по себе денежную логику не решает.

## 3. Что я рекомендую: **B + A + D** (гибрид)

Суть: **время — это товар, деньги платятся за время, а не за «периоды по факту»**.

1. **Деньги — на сервер, временем.** При Publish и по кнопке «Пополнить» деньги уходят с `Money` на серверный кошелёк `seconds`. Игрок видит «оплачено до HH:MM» и «осталось $X / N минут».
2. **Начисление — посекундное, по реальному UTC** (как сейчас, но без округления до периода). Это решает скачок на 144 периода: за 3 дня оффлайна сайт просто съест ровно столько денег, сколько на нём лежало, и встанет на паузу ровно в тот момент, когда они кончились.
3. **Оффлайн-пауза вместо `unpaid`-долга.** Кончилось время — сайт «на паузе»: домен и пакет целы, посетители получают «сайт недоступен», в панели — «Пополнить». Никаких минусов и никакого долга в сейве.
4. **Списание при заходе.** С интернетом: `stats` → сервер присылает `charged` (сколько уже удержано) и `total`; списываем `total - charged`, **и разрешаем отрицательную дельту как возврат** на `Money`. Без интернета: локальный «ожидающий» счёт тикает по UTC от последнего известного состояния и показывается как «предварительно»; при первом же соединении сервер присылает истину и разница досписывается/возвращается. Итог «списывают всю аренду при заходе» выполняется и с сетью, и без, но не превращается в неожиданный минус.
5. **Идемпотентность:** каждая операция получает `settlement_id = hash(owner|world|total|ledger_fingerprint)`. Клиент присылает его же при повторе; сервер повторный `settle` с тем же id просто возвращает текущее состояние, а не поднимает потолок заново.
6. **Терминал хостинга (D)** поверх этого: «осталось», «пауза», «пополнить», журнал, предупреждение за 5 минут. Пока — в панели хостинга редактора сайтов, отдельное приложение ОС позже.

Почему так: закрывает и «с интернетом», и «без интернета», не даёт уйти в бесконечный минус, не даёт сгорать деньгам при рассинхроне сейва, и оставляет место для «долга», если ты позже захочешь мягкий кредит доверия (например, 1 период в долг при первом запуске).

### Что придётся сделать (объём)

- `Hosting/sites/lib.php`: посекундное начисление, `wallet.seconds`/`paid_until`, `site_pause()` вместо `site_suspend()` по нехватке, `settlement_id`, разрешить возврат.
- `Hosting/sites/api.php`: `action=topup`, `action=pause|resume`, поля `seconds_left`, `paid_until`, `charged`; аккуратнее с размером `state.php`.
- `SiteHostingService.cs`: `Topup()`, `Pause()`, отрицательная дельта = возврат, локальный «ожидающий» счёт для offline-режима, запись в сейв одним `SaveData()`.
- `SiteEditorHosting.cs` + текст панели: «осталось», «пополнить», «пауза».
- Миграция старых `total`: сохранить как уже начисленный долг (не аннулировать), перевести в `seconds` по остатку `next_bill`.
- Тесты: `tools/test_site_backend.py`, `tools/test_site_extended_backend.py` — оффлайн-сценарий «ушёл на 3 дня», возврат переплаты, повторный settle с тем же id, пауза/возобновление.

### Оценка

Гибрид целиком — примерно 3–4 захода (сервер → клиент → UI → тесты). Только починка слабых мест из раздела 1 (пол/возврат/идемпотентность, без смены модели) — 1 заход.

## 5. Итог: что реализовано (2026-11-16)

Выбран гибрид **B + A + D** с уточнениями заказчика:

- **A — посекундная аренда**: $100 / 1800 с, свой домен $1100 / 1800 с (домен +$1000
  один раз), первый период вперёд, дальше — по секундам. Никаких скачков на
  $14 400 за три дня оффлайна.
- **B — тайм-банк вместо долга**: сервер тратит известные деньги сейва, кончились —
  сайт на паузе, пол 0, долг списывается (write-off). Кнопка «Пополнить +$100».
- **D — панель**: остаток денег хостинга, «хватит ещё на N минут», состояния
  «пауза: мало денег» / «домен закрепится при подключении», журнал локальных сайтов.
- **Локальный хостинг**: третий режим публикации — сайт остаётся в сейве, но
  аренда списывается с общего баланса по реально прослуженным секундам.
- **Интернет**: публикация нового домена — только онлайн (уникальность адресов
  между облачными и локальными сайтами), включение уже закреплённого и открытие
  локального сайта — офлайн.
- **Выпадающий список домена**: «Стандартный адрес / Свой домен / Локально в
  сохранении».
