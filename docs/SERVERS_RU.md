# Серверные префабы и съёмные HDD-корзины

База: пользовательский коммит `73eb52f2328836692e75de34633ad83a6bba3efa`.

## Что настроено

- `Server.prefab`: корневые `Item`, `Case`, `ServerChassis`; используется единственный исходный `Rigidbody`; обязательные ссылки Case, отдельная маленькая кнопка питания с Renderer/Receiver и событием `Case.Switch`.
- Авторские позиции, повороты, масштабы, меши, материалы, коллайдеры стенок и существующие Rigidbody сохранены. Изменены только необходимые флаги триггеров; добавлены новые компоненты/объекты.
- Слот материнской платы совместим с `Server ATX` (`match=2`). Слот БП принимает `Supply`, а не `Motherboard`; `PSUThin_2000kW` получает тег Supply, совместимый `match=2` у него уже был. Имя ресурса БП не переименовано для совместимости; реальная мощность в Supply остаётся **2000 W**, исправлена подпись.
- На Server ATX зарегистрированы все **14 реально присутствующих RAM-слотов**, оба CPU, оба кулера и USB. Новые DIMM/PCIe-гнёзда и выдуманная видеокарта не добавлялись.
- Крышка получает Item/тег Cover. Для корзин добавлены `DriveTray`, тег DriveTray и четыре отдельных гнезда крепления к корпусу. У каждого HDD-слота добавлен BoxCollider-триггер с размерами стандартного HDD.
- `Server Cover.prefab` и `Server HDD Tray.prefab` — самостоятельные Resources-предметы для восстановления снятых частей из сохранений. Существующая крышка и четыре корзины в корпусе не заменены другой геометрией.
- Вложенный авторский HDD 1TB сохранён: при обычном создании корпуса он прикрепляется к своему слоту через TryAttach, а не только выглядит вставленным.
- `sound` нового БП отключён: в нём нет AudioSource/FanSpin и отдельного меша вентилятора (дочерний Switch — не вентилятор). Вращать весь блок питания или подставлять чужой вентилятор не стали. Опциональные эффекты разрушения не обязательны для питания и сборки.
- Магазин, цены и изображения товаров этим изменением не менялись: задача — настройка присланных префабов и логики их подключения.

## Когда HDD существует для компьютера

`HDD → HardwareSlot корзины → DriveTray → Slot корпуса → Case.ActiveBoard`.

DriveTray регистрирует свой внешний drive-слот в плате только при настоящем соединении через Connector с занятым гнездом DriveTray в корпусе. Нахождение рядом с корпусом или одно лишь родительство Transform не считается подключением.

Поддержаны порядки «сначала диск в корзину» и «сначала корзина в корпус», а также установка платы последней. При снятии корзины диск удаляется из топологии платы и работающей ОС и обесточивается, но физически остаётся в корзине. При повторной установке он заново регистрируется и получает текущее состояние питания. Снятие/замена платы переводит корзины на новую плату без постоянного опроса Update/FindObjectsOfType.

Motherboard.AddExternal/RemoveExternal синхронизируют уже установленные HDD/USB и питание при горячем подключении; повторные вызовы для того же External идемпотентны. ComputerSystem не добавляет один Storage дважды. Сохраняется штатное правило: извлечение системного диска вызывает Fault; извлечение обычного дополнительного диска — нет.

## Сохранение

Используется имеющийся SaveManager с hostId/slotPath и многошаговым восстановлением: корпус → корзина → HDD. Крышка, корзины и HDD после TryAttach становятся отдельными сохраняемыми Item.

При загрузке ServerChassis удаляет встроенный заводской набор до Start и не пристёгивает его повторно: SaveManager создаёт крышку, корзины и HDD из записей сохранения. Это относится и к снятым корзинам/крышке, и к удалённому из комнаты заводскому HDD, чтобы они не возникали заново при каждом открытии .opc.

### Ручной smoke-test в Unity

1. Создать Server: крышка, четыре корзины и авторский HDD должны прикрепиться, остаться снимаемыми в removal mode и не рассыпаться при переносе корпуса.
2. Вставить Server ATX, Thin PSU 2000W, совместимые CPU/RAM/кулеры; проверить все 14 RAM и оба CPU. Для картинки с выхода платы в кабельном режиме нужен CPU с HasIntegratedGraphics (это штатное правило игры).
3. Проверить запуск кнопкой; с кабелями — штатное питание БП и видеоподключение.
4. Установить HDD в снятую корзину: BIOS/ОС не должны его видеть. Вставить корзину: диск появляется. Повторить обратный порядок.
5. На включённом ПК вынуть корзину с дополнительным диском, вернуть её несколько раз: диск пропадает/возвращается без дубликатов. Вынуть системный диск: штатный Fault.
6. Сохранить и открыть сборку: одна крышка, четыре корзины, прежнее количество HDD и их содержимое. Повторить со снятой корзиной с HDD, отдельной крышкой, вынутой платой и удалённым заводским HDD: ничего не должно восстанавливаться дополнительно.
7. Проверить обычный ATX-корпус после общих изменений Case/Motherboard.

## Уточнение: префаб, а не генерация корпуса

Все меши, кнопка и крепления сериализованы в Server.prefab. ServerChassis не содержит Instantiate/AddComponent, не имеет ExecuteAlways/ExecuteInEditMode и не выполняется при обычном перетаскивании префаба в редакторе вне Play Mode. В рантайме он только пристёгивает вложенные заводские детали через существующие слоты и убирает заводские копии при восстановлении сохранения.

Удалён ошибочно добавленный второй Rigidbody корня; исходный Rigidbody сохранён. Дочерний объект с мешем переименован из Server в Chassis Mesh: корневой Server — контейнер игрового предмета, Chassis Mesh — единственный меш его корпуса, а не второй сервер. Добавлены регрессионные проверки количества Rigidbody/Case и запрета генерации геометрии в ServerChassis.

Сообщение о двух видимых корпусах при перетаскивании префаба без Play Mode пока не воспроизведено; для подтверждения нужны скрин Scene/Hierarchy или сцена пользователя. Исправление Rigidbody не объявляется доказанной причиной появления второго видимого корпуса.
